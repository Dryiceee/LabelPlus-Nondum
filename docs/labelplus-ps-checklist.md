# LabelPlus 功能的 PS 实测清单

自动测试不启动 Photoshop，解析、匹配、取样和批处理流程用的都是模拟数据。下面这些只有在 Photoshop 里才能确认。

## 加载插件

1. 构建：`npm run build:uxp`
2. 打开 Adobe UXP Developer Tools，选 Add Plugin，指向 `uxp/manifest.json`，再点 Load。
3. 面板菜单里叫 LabelPlus-Nondum。它有自己的插件 ID（`com.dryiceee.labelplus-nondum`）和数据目录（`%APPDATA%\LabelPlus-Nondum\UXP`），可以和已安装的 TypeR 共存，但样式要重新导入。

## 准备样本

用一章真实的 LP 文本和原图，最好包含：

- 黑字白底气泡、白字黑底气泡
- 连体气泡
- 带尾巴的气泡
- 框外文字
- 灰度图和索引色 PNG

## 导入（底部工具栏的文档图标）

| # | 操作 | 预期 | 如果不对，可能的原因 |
|---|---|---|---|
| 1 | 选 LP 文本 | 显示分组和图片匹配结果，自动找到图源文件夹 | 文件读取或文件夹列举失败 |
| 2 | 生成 PSD | PSD 文件夹里出现对应文件，并生成 `labelplus-nondum.json` | `saveAs.psd` 或创建文件失败 |
| 3 | 打开一个 PSD | 每个分组一个图层组，文字在对应的组里 | 图层组或图层移动失败 |
| 4 | 查看文字 | **直排点文本**，译者的换行保留 | 方向设置失败（清单会提示 `orientation`） |
| 5 | 查看位置 | 文字的开头在标号点上 | 边界框的计算不对 |
| 6 | 查看样式 | 字体、字号、颜色、描边和分组对应的样式一致 | 样式转换失败 |
| 7 | 导入索引色或灰度图 | 成功，文档变为 RGB | `changeMode` 失败 |
| 8 | 重新导入同一文件夹 | 先询问是否覆盖 | |
| 9 | 导入一张已在 PS 中打开的图 | 清单提示文件已打开，这份文档不受影响 | |

## 整章处理

先用“先在当前文档上试”，确认没问题再跑整章。

| # | 操作 | 预期 | 如果不对，可能的原因 |
|---|---|---|---|
| 10 | 白气泡居中 | 文字居中，**没有撑开气泡的多余移动** | 取样选错区域 |
| 11 | 黑气泡居中 | 同上 | 深色分支没选中 |
| 12 | 带尾巴的气泡 | 按气泡主体居中，不被尾巴带偏 | 收缩再扩张的修正没生效 |
| 13 | 文字比气泡大 | 仍然居中，字号不变，文字超出气泡 | |
| 14 | 连体气泡 | 每句文字进入标号点所在的气泡室 | 轮廓读取或分配不对 |
| 15 | 框外分组 | 文字留在原位，不移动 | 分组规则没生效 |
| 16 | 大字（尤其拟声词）所在的气泡 | 不会把单个笔画当成气泡 | 笔画的过滤阈值需要调 |
| 17 | 套样式后查看 | **仍是直排点文本**，`!?` 直排内横排是否保留 | 样式覆盖了方向 |
| 18 | 处理后查看历史记录和选区 | 没有残留选区和工作路径，文字图层都显示 | 读取阶段的回滚没生效 |
| 19 | 整章跑完 | 文档逐个保存并关闭，内存占用不持续上涨 | |

## 涂白

在分组选项里勾选“涂白”，用“处理整章”或“先在当前文档上试”运行。“生成 PSD”只放文字，不涂白。

| # | 操作 | 预期 | 如果不对，可能的原因 |
|---|---|---|---|
| 29 | 白气泡 | 新增 `LabelPlus Clean` 图层，在图片之上、文字组之下；原文被盖住，气泡外框没被盖 | 选区或收缩没生效 |
| 30 | 米白或偏色的纸 | 填充色和纸色一致，看不出色块 | 取色不对 |
| 31 | 黑气泡白字 | 填成黑色，离外框更远（5 像素） | |
| 32 | 连体气泡 | 整个连体气泡一起涂白 | |
| 33 | 网点、渐变或灰色气泡 | 不涂，清单提示“不是纯白或纯黑” | |
| 34 | 拟声词标号落在分镜背景或黑色分镜上 | 不涂，清单提示“区域里还有别的气泡或画面” | 厚度阈值需要调 |
| 35 | 用显示或隐藏涂白层的快捷键 | 涂白层一起隐藏，原文重新出现 | |
| 36 | 同一文档“先在当前文档上试”两次 | 只有一个 `LabelPlus Clean` 图层，不会叠加 | |
